# Live AWS IAM/S3 evidence experiment — 2026-10-10

## Scope

Isolated, temporary fixture in `us-east-1` under a newly connected AWS account. A uniquely named private S3 bucket with one harmless object and an IAM role with inline `s3:GetObject` permission restricted to `fixture/*`. Role trust policy named the EC2 service principal; no instance profile or workload was created and no role session was assumed.

## AWS API observations

- `CreateBucket`, `PutPublicAccessBlock`, `PutObject`, `CreateRole`, and `PutRolePolicy` succeeded.
- `iam:SimulatePrincipalPolicy` for the role and exact object ARN returned `allowed` for `s3:GetObject` (one matched statement) and `implicitDeny` for `s3:DeleteObject` (zero matched statements).
- `s3:GetPublicAccessBlock` returned true for BlockPublicAcls, IgnorePublicAcls, BlockPublicPolicy, RestrictPublicBuckets.
- `DeleteRolePolicy`, `DeleteRole`, `DeleteObject`, and `DeleteBucket` succeeded.
- Independent follow-up `iam:GetRole` returned `NoSuchEntity`; `s3:HeadBucket` returned `404 Not Found`.

## Interpretation and falsification status

The test validates live AWS evidence acquisition and conservative interpretation: an IAM simulation `allowed` **does not prove** effective object access by an actual assumed-role session. An `implicitDeny` is a simulator result, not a general proof of impossibility under every potential policy context. No object retrieval was attempted using the fixture role. No Kubernetes, GitHub Actions, or Terraform mutation participated in this experiment. Thus it **does not** establish cross-system invariant enforcement, authorization freshness, delegation continuity, or product novelty.

The temporary fixture was removed and independently checked. AWS billing impact was not measured; do not claim zero cost.

## Next falsification gate

Compare the candidate against a strong baseline that receives the same complete, fresh evidence. If a standard centralized policy can enforce the invariant with the same evidence, do not claim the policy evaluator itself is novel. Test state-change invalidation, evidence gaps, and delegation separately.
